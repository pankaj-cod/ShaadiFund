# ADR 0006: Identifiers and money representation

**Status:** Accepted (2026-11-15)

## Decision

### Identifiers

- Primary keys are UUID v7, generated by Prisma. They are non-sequential to an outsider and time-ordered, which keeps B-tree indexes compact under heavy inserts.
- Public URLs never contain a primary key where a friendlier or safer handle exists:
  - weddings use `slug` (`/wedding/riya-and-rahul`), lowercase letters, digits and hyphens, 3 to 60 characters, with a reserved-word list;
  - guest acknowledgment pages use `acknowledgmentToken`, 32 random bytes, base64url.
- Dream ids appear in public URLs. They reveal an approximate creation time, which is acceptable.

### Money

- Every amount is an integer number of paise in a column named `*Paise`. No floats, no decimals, anywhere.
- Columns are 32-bit integers. The service layer caps a dream target at ₹1,00,00,000 and a single contribution at ₹5,00,000, both far below the 32-bit limit.
- Limits, suggested amounts and the fee rate live in `PlatformConfig`, with defaults in code.
- Fee calculation is one pure function using integer arithmetic with explicit rounding (round half up to the nearest paise). The stored `platformFeePaise` and `totalPaise` are authoritative; they are never recomputed later.
- Formatting to rupees happens only at the display edge, using `Intl.NumberFormat("en-IN")`.
- Currency is stored as an ISO code and is always `INR` for now.
